# 塔罗引擎：牌库、牌阵与评分

## 数据颗粒度决定解读质量

同一套算法，牌库写得粗，解读就像百度百科；牌库写得细，用户会觉得"它懂我这段关系"。

**关键做法：每张牌除了通用牌义，单独写一份场景牌义。** 做合作占卜就写"合作场景含义"，做感情就写"感情场景含义"。通用牌义谁都能抄，场景牌义是产品价值所在。

## 牌库字段设计

78 张 = 大阿尔卡纳 22 + 小阿尔卡纳 56（权杖、圣杯、宝剑、星币各 14）。

```js
{
  id: 'ma00',            // 唯一标识：ma=大牌, w/c/s/p=四花色 + 序号
  n:  '愚者',             // 中文名
  en: 'The Fool',        // 英文名
  s:  null,              // 花色：null | 'wands' | 'cups' | 'swords' | 'pentacles'
  k:  0,                 // 序号
  u:  ['新的开始、冒险、自发',        // 正位：关键词
       '一段全新旅程的起点，带着天真与勇气迈步。',  // 正位：通用含义
       '合作：崭新的合作关系，彼此还在试探，充满可能性但也缺乏规则。'], // 正位：场景含义
  r:  ['鲁莽、准备不足、轻率',
       '仓促行动，缺乏计划就投入。',
       '合作：贸然联手，对彼此能力与责任未做评估。建议先补上背景了解与分工约定。']
}
```

三个字段一组的设计理由：

- **关键词**：用于列表、标签、摘要显示
- **通用含义**：作为解读的主体句
- **场景含义**：让解读落到用户的具体处境，通常自带一条行动建议

字段名用短名（`u`/`r`/`n`）是为了压缩体积——78 张牌全量中文文案很容易到 100KB 以上，而移动端首屏加载希望更快。若可读性优先，可改长名，代价是体积。

> 场景含义里写"建议……"，比只描述状态有用得多。用户要的是下一步怎么办。

## 牌阵定义

牌阵 = 有序的牌位列表。每个牌位需要能回答：**这次落在哪个问题上**。

```js
window.SPREADS = {
  partnership: {
    id: 'partnership',
    name: '合作契合牌阵',
    sub: '深度看清一段合作关系',
    desc: '从双方状态、关系现状、潜在风险到行动建议与未来走向。',
    cardCount: 6,
    positions: [
      { key:'self',      label:'你的状态',  hint:'你在这段合作中的角色、心态与优势', focus:'你' },
      { key:'other',     label:'对方状态',  hint:'合作伙伴的真实状态、能力与核心诉求', focus:'对方' },
      { key:'now',       label:'合作现状',  hint:'这段关系当下的真实样貌', focus:'关系' },
      { key:'challenge', label:'潜在挑战',  hint:'需要警惕的隐藏风险与分歧点', focus:'风险' },
      { key:'advice',    label:'行动建议',  hint:'改善与推进这段合作的具体做法', focus:'建议' },
      { key:'future',    label:'未来走向',  hint:'若维持现状，这段合作将走向何方', focus:'走向' }
    ]
  }
};
```

好牌阵的四个特征：

1. **顺序有叙事逻辑**：先看双方，再看关系，再看风险，最后给建议和走向
2. **每个牌位一句话说清问的是什么**（`hint`），用户才知道该怎么理解
3. **必须有"行动建议"位**，纯预测不给建议的占卜没有实用价值
4. **张数克制**：3 张做快速决策，6 张做深度分析，超过 8 张用户会失去耐心

配套一份牌位引导语，让文案拼接自然：

```js
window.POSITION_LEAD = {
  self:     '在这段合作中，你此刻的状态是——',
  other:    '对方在这段关系中的真实状态是——',
  challenge:'这段合作里需要警惕的是——'
};
```

## 抽牌：随机性要真

```js
function draw(spreadId, count) {
  const pool = TAROT_DECK.slice();
  const cards = [];
  for (let i = 0; i < count; i++) {
    const idx = Math.floor(Math.random() * pool.length);
    const card = pool.splice(idx, 1)[0];        // 抽出即移除，保证不重复
    cards.push({ card, reversed: Math.random() < 0.35 });  // 逆位概率
  }
  return { cards };
}
```

要点：

- 用 `splice` 抽取，**天然避免重复牌**
- 逆位概率取 30%~40%（传统上约一半，但逆位解读偏负面，占比过高会让结果压抑）
- 不要用 `Date.now()` 当种子——同一秒内多次占卜会得到完全相同的结果

## 评分：简单规则比复杂模型更可信

```js
// 1. 单张牌吉凶：普通牌正位 +1 / 逆位 -1；警示牌相反
function cardScore(card, reversed) {
  if (isWarning(card.id)) return reversed ? 1 : -1;
  return reversed ? -1 : 1;
}

// 2. 归一化到 0-100，留出余地不出现极端值
let score = 50 + (total / n) * 38;
score = Math.max(5, Math.min(95, Math.round(score)));
```

**警示牌逆位反而是好信号**——"塔"逆位意味危机被延缓或已渡过，"恶魔"逆位意味正在摆脱不健康绑定。这个细节会让懂塔罗的用户明显感到"这东西是认真做的"。警示牌清单：塔、恶魔、死神、月亮、宝剑十/九/三/五/八、圣杯五/八、星币五、权杖十/五。

等级划分（阈值可按产品调，但要保持单调）：

| 分数 | 等级 | 总评语气 |
|---|---|---|
| ≥80 | 高度契合 | 值得深交 |
| ≥65 | 总体向好 | 基本面不错，留意卡点 |
| ≥45 | 喜忧参半 | 有潜力，需主动经营 |
| ≥30 | 挑战较多 | 推进前先谈清分歧 |
| <30 | 阻力较大 | 建议暂缓，先补信任 |

**为什么不做"AI 打分"**：分数需要可解释、可复现。用户问"为什么是 62 分"，规则引擎能答上来（哪几张牌拉低、五行关系扣了几分）；黑箱模型答不上来，反而降低信任。

## 解读文案的组合

```js
sections = cards.map((c, i) => {
  const pos = spread.positions[i];
  const src = c.reversed ? c.card.r : c.card.u;
  return {
    label: pos.label,
    keyword: src[0],
    lead: POSITION_LEAD[pos.key],
    body: src[2],            // 用场景含义，不用通用含义
    general: src[1]
  };
});
```

三条经验：

1. **优先用场景含义**（`src[2]`），通用含义只在需要解释"这张牌本身是什么"时补充
2. **每个牌位独立成段**，不要把所有牌揉成一大段——用户要能逐条看
3. **结尾给 2-3 条可执行建议**，从"行动建议"位的牌义里提取动词短语，别写"多沟通"这种废话，要写"下次谈之前先把分成比例写成文字"

## 自测要覆盖什么

- 78 张牌齐全，id 无重复
- 抽 6 张无重复牌
- 正逆位都能取到对应文案，无 `undefined`
- 分数落在 5~95 之间，且等级与分数单调一致
- 每次抽牌结果不同（连续抽 20 次，至少 15 种不同组合）

这些检查写成 `tests/smoke.js`，用 `node` 直接跑，不需要浏览器。
